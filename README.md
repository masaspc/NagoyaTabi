# 名古屋 王道 2026.8.11-12

2026年8月11日（火・山の日）〜12日（水）の名古屋1泊2日の旅を、現地から開いて使うための静的サイト。

- 往路 東京 10:12発 のぞみ ／ 11:48 名古屋着（所要1時間36分）
- 復路 名古屋 14:49発 ／ 16:24 東京着
- 公開: <https://masaspc.github.io/NagoyaTabi/>

## 出発前に必ず確認すること（1）入場方法

**営業時間が分かっても「入れるか」は分からない。** 2026-08-12 にこれで失敗した——
ポケモンセンターナゴヤは混雑期に当日整理券制で、8月は土日祝に加えてお盆の混雑予想日
（8/10-16）が対象、配布は9:00から。公式サイトで7月に告知されていたのに、営業時間
（10:00-21:00）だけを見て「開店に行けば入れる」と組んだ。結果、8/11に入れず、
8/12の午前へ回し、**ポケモンセンターへ2回行くことになり、徳川美術館は訪問できないまま
旅が終わった。1件の見落としが行程2コマ分の崩壊になった。**

そのため名所データは `entry`（入場方法）を持つ。

| 欄 | 内容 |
|---|---|
| `kind` | `free` / `queue` / `ticket`（当日整理券）/ `lottery`（抽選）/ `reserve`（要予約）/ `timed`（時間指定） |
| `checkedVia` | 何を見て判断したか。`official-news` / `official-site` / `phone` / `onsite` |
| `checkedOn` | 確認日（YYYY-MM-DD） |
| `url` | 根拠のURL（`free` 以外は必須） |
| `note` | 分かったこと。分からなかったことは「未確認」と書いて残す |

**この確認は人の記憶に置かない。** 最初の再発防止は「出発前に確認する」という
チェック項目だったが、それは弱い——人は忘れるし、忘れたことに気づけない。
いまは `tools/check-entry.mjs` が、行程の指す名所すべてについて次を検査し、
足りなければ**終了コード1で落とす**（`.github/workflows/check.yml` が push と PR で走らせる）。

- `entry` が無い／`kind`・`checkedVia`・`checkedOn` が不正
- `free` 以外なのに根拠（`url` / `tel` / `official`）が無い
- 確認日が旅の開始から30日より前（**整理券や抽選の告知は旅の直前に出る**ので、古い確認は
  確認していないのと同じ）

加えて、`ticket`/`lottery`/`reserve`/`timed` なのに `checkedVia` が `official-news` でない場合と、
`note` に「未確認」が残っている場合は警告として一覧に出る（落としはしない）。

**名所を1件足すときは、営業時間のページではなく公式サイトの「お知らせ」を開くこと。**
お盆・年末年始・連休は特に。表示側では、`entry` の無い名所は「未確認」として最も強い警告になり
（`assets/entrycheck.js`）、確認表が実用メモ 01「出発前チェック」の先頭に出て、
行程の各コマにもバッジが付く。

## 検査

ビルドは無いが、手で守っていた約束ごとだけは機械に見させる。

```
node tools/check-entry.mjs      # 入場方法の記入もれ
node tools/check-precache.mjs   # sw.js の PRECACHE と VERSION
```

`check-precache.mjs` は、各ページが読む同一オリジンのファイルが `PRECACHE` に載っているか、
`NT.PAGES` のページが漏れていないか、`PRECACHE` に存在しないファイルが無いかを見る。
さらに **`PRECACHE` 対象を変更したのに `VERSION` を据え置いていたら落とす**——
上げ忘れると、ホーム画面に追加済みの端末が古い版を表示し続けるため。

## 出発前に必ず確認すること（2）電話で確かめる店

**味処 叶（052-241-3471）**は定休が月・火だが、「祝日の場合は次の日が定休日」という
振替ルールがある。8/11は山の日（祝日）にあたるため、**8/11は営業、振替で8/12（水）が
定休になる可能性が高い**——当初プランの逆になる。

**あつた蓬莱軒 神宮店（052-682-5598）**も定休が火・第2第4月曜で「祝日は営業、その場合は
振替休あり」という同じ形のルールを持ち、**8/12に振替休がかかるリスク**がある。

プランA はこの2軒のリスクを避けて8/11に叶へ行き、8/12のひつまぶしは年中無休の
まるや本店に寄せて組んである。プランBはあつた蓬莱軒 松坂屋店が祝日（8/11）に
11:00-20:30の通し営業をしていて、行列ができても待ちきれると分かった場合に
切り替えてよい（行程ページの「01 プラン」から切替可能）。

「メモ」ページの営業時間表では、この2軒を含め判定が確定できない店はすべて
**「要確認」**と表示し、電話番号を店名の下に添えてある。「要確認」を見たら、
出発前に必ず電話で確かめること。

## 使い方

5ページ構成。下部ナビ（またはスワイプ）で行き来する。

- **行程** — 先頭に名古屋の今の天気と8/11・8/12の予報が出る（後述）。
  端末の時計から今のコマを自動で強調し、次の予定までの残り時間を出す。
  「今ここ」ボタンで実際にいる場所を記録すると、遅れを検知して同じ日の中から
  削れるコマを提案する（リカバリ）。雨・猛暑・行列のボタンでその場のコマを
  代替に差し替えられる。プランA／プランBの切替もここから
- **名所** — 30箇所。すべてに「ここだけは見る」（見どころ）・「回り方」（順路）・
  「撮るなら」（撮影のコツ）を用意した。エリアで絞るか、現在地から近い順に
  並べ替える。豆知識ガチャもここ
- **名物** — 20品。五食の枠の制覇状況と、写真つきの記録（チェック・メモ・写真）
- **メモ** — 出発前チェック（持ち物・やることの35項目。チェックは端末に残り、
  印刷すれば手で潰せる紙のリストになる）、1泊2日の進め方（前日の準備から
  帰りの列車の逆算まで、はじめての名古屋を時系列で案内する9枚）、
  営業時間の一覧、移動の早見表、土産の買い物リスト、地下鉄マップ、
  立替・割り勘の記録、旅の終わりに出る記録まとめ画像、公開URLのQRコード
- **あそび** — 電車の中や順番待ちで、ふたりで回して遊ぶもの。豆知識対戦クイズ
  （全40問の三択）、ミッションカード（現地で挑戦する24枚）、名古屋めし総選挙
  （名物ページで付けた★評価の集計と「一番もめた1品」）

豆知識対戦クイズ・名古屋めし総選挙・立替割り勘は同じふたりの名前を共有する
（`NT.players()` が唯一の情報源）。どれか1つで名前を決めれば、残り2つにも
そのまま引き継がれる。

持ち物チェック・名物のチェック・メモ・写真・プラン選択・デモ時計・
クイズやミッションの進行・割り勘の記録などは端末のブラウザ内
（localStorage / IndexedDB）に保存され、ページを閉じても消えない。

スマートフォンのホーム画面に追加しておくと、地下街で電波が弱くても・機内モードでも
開く（Service Worker によるオフラインキャッシュ）。

## 天気について

行程ページの先頭に、名古屋の現在の気温・天気と、8/11・8/12の予報（最高／最低気温、
降水確率、行程が動いている時間帯の3時間おきの降水確率）が出る。数字を並べるだけでなく、
**大盆踊り（8/11 18:00-20:00）の時間帯の降水確率**・**猛暑日になる日**を拾って、
その場で「雨モード」「猛暑モード」（状況切替）に移れるボタンを添える。

取得先は [Open-Meteo](https://open-meteo.com/)。**APIキーが要らないことがこの選択の
理由**——このサイトはビルドもサーバーも無く、書いたものがそのまま公開されるので、
キーの要るサービスはキーを公開することになり使えない。

`sw.js` の fetch ハンドラは別オリジンを素通しするので、この応答はキャッシュされない
（＝機内モード・圏外では必ず失敗する）。そこで取得できた内容を旅の2日ぶんに畳んで
localStorage（`nt:weather`）に持ち、電波が無いときは**「何時時点の予報か」を明示した
うえで**前回の内容を出す。一度も取得できていなければ、その旨と再試行ボタンだけを出す。
いずれの場合も行程・名所・名物の表示には影響しない。

自動で取り直すのは、ページを開いたときと、画面に戻ってきたときの2回だけ（前回から
10分以内なら何もしない）。すぐ最新にしたいときはカード右上の「更新」を押す。

## 見た目・演出について

見出しは明朝体（Shippori Mincho B1）、本文はゴシック体（Zen Kaku Gothic New）、
数字類は等幅（Space Mono）——いずれも Google Fonts から読み込む。名所・名物カードには
分類ごとの色とアイコン（`assets/art.js`）、行程の目玉コマと一部のカードには名所の線画、
ページ見出しには金鯱や名所のさりげない透かしが付く。スクロールで内容が浮かび上がる
演出・ページ見出しのパララックス・達成時の光の粒（`assets/fx.js`）も入っている。

**Webフォントはオフラインでは読み込まれない（意図的）。** Service Worker がキャッシュ
するのは同一オリジンのファイルだけで、Google Fonts は最初から `PRECACHE` の対象外。
電波が無い・機内モードのときは、フォントの読み込みが静かに失敗し、OSの標準の
明朝体・ゴシック体・等幅フォントへそのまま切り替わる——文字が欠けたり四角
（tofu）になったりはしない。エラーも出ない。同様に `assets/fx.js` が万一読み込めなくても
（ネットワーク不調・キャッシュ破損など）演出が付かないだけで、行程や名所・名物の
本文はすべて最初から見える状態を既定にしてある（`assets/fx.js` に依存して初めて
見える、という向きの作りにはしていない）。`prefers-reduced-motion` を有効にしている
端末では、演出そのものが最初から動かない。

表示テーマは端末設定に追従する「端末設定」・常に明るい「昼」・常に暗い「夜」の3状態を
右上のボタンで回せる。印刷（ブラウザの印刷機能）では、これらの装飾・演出はすべて消え、
白地に黒文字・営業時間表は全列そのままの資料になる——電池切れの保険として紙に
出すことを想定した挙動。

## 更新のしかた

情報は `data/` の9ファイルに集約してある。**店を1軒足す・クイズや豆知識カードを
1枚足すだけなら、該当ファイルの配列に要素を1つ足すだけでよい**（ファイルは
増えないので `sw.js` の変更は不要）。

| ファイル | 内容 |
|---|---|
| `data/spots.data.js` | 名所（回り方・見どころ・撮影のコツを含む） |
| `data/foods.data.js` | 名物 |
| `data/trip.data.js` | 行程（プランA / プランB） |
| `data/transit.data.js` | 移動区間 |
| `data/trivia.data.js` | 豆知識カード（豆知識ガチャ・対戦クイズの種本） |
| `data/omiyage.data.js` | 土産 |
| `data/quiz.data.js` | 豆知識対戦クイズの設問40問 |
| `data/missions.data.js` | ミッションカード24枚 |
| `data/prep.data.js` | 出発前チェック（持ち物・やること）と1泊2日のノウハウ |

`data/prep.data.js` の項目 `id` は持ち物チェックの保存キー（`nt:packing`）そのもの。
**一度公開した `id` は変えないこと**——変えると、すでにチェックを付けた端末で
そのチェックが消える。項目を削るときも、その `id` を別の項目に使い回さない。

ビルドは無い。編集して `git push` すれば GitHub Pages にそのまま反映される。

### ファイルを新しく追加したときは要注意

`data/` に新しいファイルを作る・`assets/` に新しい `.js`/`.css` を足すなど、
**ページが `<script src="...">` や `<link href="...">` で読み込むファイルを
新規に追加した場合は、`sw.js` の `PRECACHE` 配列と `VERSION` の両方を必ず更新すること。**

更新を忘れると起きること:

- **`PRECACHE` に追加し忘れた場合** — オフライン時（機内モード・地下街）にそのファイルだけ
  読み込めない。今の `sw.js` はナビゲーション（ページ遷移）以外の失敗を握りつぶさず
  そのまま失敗させるため、原因不明の白画面ではなく該当スクリプトのエラーとして
  表面化するが、いずれにせよそのページの機能が欠けたまま動く
- **`VERSION` を上げ忘れた場合** — 中身を変えたファイルがあっても Service Worker は
  「新しいキャッシュを作る理由」を見つけられず、**既にホーム画面に追加した端末では
  古い版のまま表示され続ける**。オンラインであっても、キャッシュ済みのファイルは
  ネットワークより先に返るため気づきにくい

`PRECACHE` は手書きの配列（ビルドで自動生成していない）。5ページの `<script>`/`<link>`、
`manifest.webmanifest`、アイコンと、`data/` の9ファイルを漏れなく列挙する必要がある。
**Google Fonts への `<link>`（`fonts.googleapis.com`/`fonts.gstatic.com`）は対象外**——
別オリジンなので `sw.js` の fetch ハンドラも素通しする設計であり、`PRECACHE` に足しても
意味がない（キャッシュされず、足すこと自体が誤り）。フォントが読めないときは
システムフォントへ自動で落ちるので、これで正しい。
