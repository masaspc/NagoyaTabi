# 名古屋旅ガイドサイト 設計書

- 作成日: 2026-08-08
- 対象の旅: 2026年8月11日（火・山の日）〜8月12日（水）／東京発 1泊2日
- 公開先: GitHub Pages
- 前身: `/Users/masa/Downloads/nagoya-oudou-final.html`（確定プラン。デザインとプラン内容を継承する）

## 目的

現地で開いて使う旅の司令塔をつくる。確定した行程を表示するだけでなく、
予定が崩れたとき（行列が長い、猛暑、雨、時間が押した）にその場で判断を差し替えられること、
名所と名物の豆知識をすぐ引けることを最優先する。

旅の3日後には本番を迎えるため、実装は静的ファイルのみで完結させ、ビルド工程を持たない。
`git push` した内容がそのまま GitHub Pages に反映される状態を保つ。

## 制約と前提

- 閲覧環境はスマートフォン（幅375px）が主。PCは副。
- 地下街・地下鉄内では通信が不安定になる。外部APIへの実行時依存を持たない。
- 外部ライブラリを読み込まない。CDNへの依存はオフライン時に壊れるため、必要なものは自前実装する。
- ESモジュールを使わない。`file://` で直接開いても動くよう、素朴な `<script src>` とグローバル名前空間で構成する。
- 8月の名古屋は日中35℃を超える。屋内か屋外かは一級の情報として扱う。

## 情報の正確性の方針

営業時間と定休日は旅の成否を左右するが、お盆期間（8/13-16）の臨時休業が個人店に発生しうるため、
記憶だけで書くと外れる。次の扱いを全データに適用する。

- 各レコードは `verifiedOn`（確認日）と `official`（公式URL）を持つ。
  （利用者のチェックボックス状態を指す `nt:checks` とは別物のため、名前を分けている）
- 実装前に主要25件（行程に登場する店・施設と、代替候補の主要どころ）を Web で裏取りする。
- 裏取りできなかったものは `unverified: true` を立て、画面に「要確認」バッジと公式リンクを出す。
  推測を確定情報として表示しない。
- 歴史・由来などの豆知識は変動しないため、この扱いの対象外とする。

## デザインシステム

前身ファイルの意匠を共通CSSに昇格させる。

- 色: 六浄緑 `#1D5C55` / 深緑 `#0D2B28` / 金 `#C79A3C` / 味噌 `#6B3226` / 紙 `#EAEDE6` / 墨 `#1E2523`
- 書体: 見出し Shippori Mincho B1、本文 Zen Kaku Gothic New、数値と符号 Space Mono
- 罫線を細く、角丸を2〜3pxに抑えた印刷物寄りの質感を保つ

夜モードは上記を反転ではなく再配色する。紙 → 墨、六浄緑を明度を上げて可読性を確保し、金は彩度を落とす。
`prefers-color-scheme` に自動追従し、手動トグルで上書きできる。上書きは `nt:theme` に保存する。

データファイルは `(window.NT ||= {}).spots = [...]` の形で単一のグローバル `NT` に集約する。
ページごとの JS は `NT` を読むだけで、データの取得方法を知らない。
「店を1軒足す」がデータ配列への1要素追加で済む状態を維持する。

`assets/` と `data/` でファイル名が衝突しないよう、データ側は `*.data.js` とする。

## 各ページの仕様

### index.html — 行程

前身ファイルのタイムライン表示を踏襲し、以下を追加する。

**今ここ追尾**（`itinerary.js`）
端末時刻から現在のコマを判定して強調し、そこへ自動スクロールする。
次の予定までの残り時間を表示する。旅程外の日時（8/11より前、8/12より後）に開いた場合は
追尾を無効化し、代わりに「デモ時刻」セレクタを出す。旅の前に動作を確認できるようにするためで、
選んだ時刻は `nt:clock` に保存し、すべての時刻依存機能がこの時刻源（`core.js` の `now()`）を参照する。

**遅延リカバリ**
遅延の求め方を2段構えにする。強調するコマの判定は常に時刻源による。

1. 各コマの「今ここにいる」ボタンが押されていれば、押した時刻とそのコマの予定時刻の差を遅延とする（明示）。
2. 押されていなければ、時刻源が現在のコマの予定終了時刻を過ぎているかで遅延を推定する（暗黙）。

明示があれば常にそちらを優先する。遅延が15分を超えたら、後続アイテムのうち `flex` が大きいものから
順に短縮案を組み立て、次の `hardDeadline` に間に合うかを判定して1〜2案を提示する。
削れる余地が足りない場合は「何を落とすか」の候補を出す。予定データは書き換えず、提案のみ行う。
「今ここ」の押下記録は `nt:progress` に保存する。

**状況切替**
`[通常] [☂雨] [🌡猛暑] [行列が長い]` のトグル。押すと該当コマのカードが `alts` の内容に差し替わる。
DOMの入れ替えのみで通信は発生しない。選択は `nt:situation` に保存する。

**地下鉄マップ**
`subwaymap.js` が描くSVGを折りたたみで格納。ピンのタップでそのスポットの詳細へ飛ぶ。

### spots.html — 観光名所 図鑑

カードのアコーディオン一覧。エリアタブでフィルタ。`屋内` / `日陰` バッジ。
「現在地から近い順」ボタンで Geolocation を要求し、Haversine で距離を出して並べ替える。
許可されなかった場合・取得失敗時はエリア順に戻し、理由を1行で表示する（無言で失敗しない）。
訪問済みチェックを持ち `nt:visited` に保存、サマリーの材料にする。

### gourmet.html — 名古屋名物 図鑑

名物カードに 由来 / 食べ方 / 食べられる店 を格納。
**五食制覇メーター**を先頭に置く。五つの食事枠と名物の制覇状況をリング表示する。
各名物にチェックボックス、写真1枚、ひとことメモを添えられる。
写真は容量が大きいため IndexedDB（`nt-photos`）に Blob で保存し、
チェックとメモは localStorage（`nt:checks`）に置く。写真は保存前に長辺1600pxへ縮小する。

### tips.html — 実用メモ

- **営業時間・定休日の一覧表**: 全店舗・施設を1表に。「8/11(火・祝)」「8/12(水)」の2列で
  その日に開いているかを ○ / × / 要確認 で示す。味処 叶が8/11に休みである等の判断が1画面で付く。
- **移動早見表**: `transit.data.js` から路線・所要分・運賃。
  ドニチエコきっぷは土日祝のみ有効なので8/11は使えて8/12は使えない、という注意を添える。
- **土産の買い物リスト**: 候補から選んで、誰用・個数を入れる。買える場所と、帰りの新幹線に対する
  購入締切時間を表示。チェック状態は `nt:omiyage` に保存。
- **QRコード**: サイトURLのQRを `qr.js` が canvas に描く。同行者に見せて渡す。
  外部ライブラリを使わないため自前実装とする。誤り訂正レベル L、8bitバイトモード、
  バージョン1〜7を文字数から自動選択する範囲に限定する（サイトURLは50文字程度で収まる）。
  収まらない長さを渡された場合はQRを描かず、URLの文字列表示にフォールバックする。
- **暑さ対策・持ち物**: 静的な散文。

### 全ページ共通

- **スワイプでページ送り**: 行程 → 名所 → 名物 → メモ の順で左右スワイプ遷移。
  縦スクロールと競合しないよう、横移動が縦移動の2倍かつ40px超のときだけ発火させる。
- **夜モード**トグル（ヘッダー）。
- **印刷レイアウト**: 行程と営業時間表がA4に収まる `@media print`。ナビ・ボタン・トグルは印刷しない。
  充電切れへの保険。
- **旅サマリー**: `summary.js` が `nt:checks` / `nt:visited` / メモから縦長画像を canvas に描き、
  保存できるようにする。旅程終了後（8/12 以降）に tips ページ上部へ導線を出す。

## PWA

`manifest.webmanifest` にアイコン・テーマ色・`display:standalone` を定義し、ホーム画面に追加できるようにする。
`sw.js` はインストール時に全ファイルを precache し、cache-first で応答する。
precache の対象は手で並べたファイル一覧とする（ビルドがないため自動生成しない）。
ファイルを追加したら `sw.js` の一覧とバージョン文字列の両方を更新する必要がある、という運用上の負債を
承知の上で選ぶ。ファイル数が20前後で固定されるため、自動化のコストに見合わない。
Service Worker は `file://` では動かないが、その場合も機能が落ちるだけでページは動作する。

## 公開

GitHub Pages の公開元を `main` ブランチのルートに設定する。ビルドがないため GitHub Actions は使わない。
リポジトリ名から `https://<user>.github.io/NagoyaTabi/` で配信される想定で、
ページ間リンクと `manifest` / `sw.js` のパスはすべてルート相対ではなく相対パスで書く。
サブディレクトリ配信でも `file://` でも同じHTMLが動くようにするためで、この制約は実装中に破らない。

## 動作確認

自動テストは置かない。静的サイトで、判断の中心が「現地で読めるか」にあるため、次を手で確認する。

1. 4ページが GitHub Pages と `file://` の両方で開き、コンソールにエラーが出ない
2. 幅375pxで横スクロールが発生しない（表は表単体で横スクロールする）
3. デモ時刻を 8/11 15:24 に設定 → 現在のコマが強調され、次の予定までの残りが出る
4. デモ時刻を 8/11 19:30（予定より遅い）に設定 → リカバリ案が名古屋城の閉園に言及する
5. 状況切替の4状態で、代替を持つコマが差し替わる
6. 機内モードで再訪しても4ページとも開く
7. 夜モード・印刷プレビュー・スワイプ遷移が破綻しない
8. チェック / メモ / 写真 / 土産リストがリロード後も残る
9. QRを実機カメラで読み取ってURLに解決する
10. 位置情報を拒否した場合に、理由が表示されエリア順に戻る

## やらないこと

- 外部の天気APIや地図タイルの読み込み（オフライン要件と衝突する）
- ルート検索・乗換案内の自前実装（Googleマップへのリンクで代替する）
- 予約機能・決済・アカウント
- ビルドツール、フレームワーク、CDNライブラリ
- 遠方（ジブリパーク、犬山、常滑）の網羅。1泊2日の動線から外れる
